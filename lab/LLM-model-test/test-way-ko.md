## 1. 개요: LLM 파이프라인 아키텍처

모든 평가 실험이 하나의 엔지니어링 원칙으로 수렴합니다: **"믿지 말고 검증한다"** (Don't trust — verify). LLM은 블랙박스가 아니라 계약으로 제약된 컴포넌트입니다:

```
입력 (ASR 전사 + 컨텍스트) → [프롬프트 계약: 역할, 예산, 펜싱]
     → [모델 로드 래더: fp16 → 정상성 프로브 → 4bit NF4 폴백]
     → [가드 생성 루프: JSON 모드 → 스키마 게이트 → 재시도 → 폴백]
     → [출력 계약: 검증된 dict]
     → [다운스트림: TTS / 노트 포맷팅 / 스트림 프로세서]
```

## 2. LLM 모델 평가 핵심 지표

### 2.1 지연 지표 (음성 에이전트 핵심)

| 지표 | 정의 | 예산 | 비고 |
|---|---|---|---|
| **TTFT** (Time To First Token, 첫 토큰 시간) | 요청 전송 → 첫 토큰 수신 | 체감 반응성 | API는 서버 큐잉이 지배 |
| **TTFA** (Time To First Answer, 첫 답변 시간) | 요청 → 첫 *답변* 토큰 (`</think>` 이후) | 음성 에이전트 ≤ 500ms | 추론형 모델: TTFA >> TTFT |
| **TTFS** (Time To First Sentence, 첫 문장 시간) | 요청 → 첫 완전한 문장 | TTS 핸드오프 게이트 | TTS 겹침에선 TTFT보다 중요 |
| **TTFS − TTFT 격차** | 첫 토큰과 첫 문장 사이 시간 | 겹침 예산 | Gemma E2B: ~797ms; EXAONE 1.2B: ~72ms |
| **E2E 지연** | 입력 → 최종 검증 출력 | 발화당 ≤ 2.5s | ASR + LLM + 검증 포함 |
| **처리량** (tokens/s 또는 chunks/s) | 지속 생성 속도 | 문장 경계 겹침 결정 | 스트리밍 UX는 TTFT보다 처리량 |

### 2.2 계약 준수 지표

| 지표 | 정의 | 목표 |
|---|---|---|
| **준수율** | 유효 출력 / 총 시도 | 5/5 (100%) |
| **재시도 횟수** | 발화당 필요한 재시도 | 0 (첫 시도 성공) |
| **스키마 위반율** | jsonschema 게이트 실패 출력 | 프롬프트 + 퓨샷 후 0% |
| **비-JSON율** | JSON이 아닌 출력 비율 | 0% |
| **펜스 제거 성공률** | 마크다운 펜스에서 깨끗한 JSON 추출 | 100% |

### 2.3 품질 지표

| 지표 | 정의 | 측정 방법 |
|---|---|---|
| **CER** (Character Error Rate, 문자 오류율) | ASR 전사 정확도 | 공백 제거 Levenshtein vs 참조 |
| **한글 비율** | 출력 내 한국어 문자 비율 | `hangul_chars / alpha_chars`; T=0.1 → ≥0.984 |
| **한자 오염** | 한국어 출력 내 CJK 통합 한자 | `hanja > 0`이면 플래그 (Qwen3 혼용 경향) |
| **응답 길이** | 계약 한도 대비 문자 수 | ≤ 200자 (TTS 약 15초) |
| **앵무새 / OOD 일반화** | 분포 외 발화 처리 | 미공개 시나리오 3개로 프로브 |
| **코드 스위칭** | 한국어 출력 내 외국어 혼용 | 한글 비율 + 수동 검수 |

### 2.4 배포 지표

| 지표 | 중요 이유 | T4 제약 |
|---|---|---|
| **VRAM (GB)** | T4 16GB에 탑재 가능 여부 | fp16: 파라미터 × 2바이트; NF4: 파라미터 × 0.55 × 1.3 마진 |
| **모델 로드 시간 (초)** | 콜드 스타트 UX | Gemma E2B: ~10s; EXAONE 1.2B: ~3s |
| **양자화 허용 오차** | 속도/정확도 트레이드오프 | NF4는 VRAM 확보, 소형 모델에선 속도 비용 |
| **batch=1 처리량** | 실시간 단건 지연 | 자기회귀 패널티가 출력 길이에 비례 |
| **라이선스** | 상업 배포 합법성 | MIT ✓, CC-BY-NC ✗, qwen-research ✗, llama3.2 ✓ |

## 3. 성능 개선 처리 방법

### 3.1 프롬프트 엔지니어링 (계약 기반)

| 방법 | 상세 | 효과 |
|---|---|---|
| **역할 구조** | system → user → assistant; system은 정확히 1회, 첫 번째, user로 끝남 | 템플릿 준수 강제 |
| **데이터 펜싱** | 고객 발화를 `<고객발화>` 태그로 감싸고 명령 아님을 선언 | 주입 공격 저항 |
| **토큰 예산** | system + 최신 user는 불가침; 오래된 중간 턴부터 제거 | 조용한 잘림 방지 |
| **퓨샷 앵커링** | 목표 포맷과 일치하는 예시 출력 2-3개 | 게이트 위반 60% → 10% |
| **상태 머신 조건화** | 대화 상태(ASK_NEED/CONFIRM/PROCESS/CLOSE)에 따라 system 프롬프트 변경 | 맥락에 맞는 응답 |
| **TTS 안전 출력 규칙** | 숫자는 한국어 발음으로, 기호/이모지 금지 | TTS 실패 방지 |
| **ASR 신뢰도 변조** | CER 낮음 → "추측하지 말고 확인 요청" 지시 | 환각 억제 |

### 3.2 출력 검증 (가드 생성 루프)

```
1. JSON 모드(서버) 또는 프롬프트 지시(로컬)로 생성
2. 마크다운 펜스 제거
3. jsonschema로 검증
4. 유효하지 않으면 → 정확한 오류 메모로 재시도 (누락 키 이름 명시)
5. 여전히 유효하지 않으면 → 안전 폴백 응답
6. 절대 예외 던지지 않음 — status dict 반환
```

| 계층 | 목적 | 실패 모드 |
|---|---|---|
| JSON 모드 / `response_format` | "JSON임"을 보장 | 스키마 일치를 보장하지 않음 |
| 프롬프트 지시 | 스키마 준수 유도 | 확률적, 보장되지 않음 |
| jsonschema 게이트 | 구조 검증 | 프롬프트가 놓친 것 포착 |
| 오류 메모 재시도 | 누락 키 구체적 수정 | 지연 예산 소모 |
| 안전 폴백 | 우아한 성능 저하 | 일반적이지만 유효한 응답 |

### 3.3 모델 선택 프레임워크 (세 가지 필터)

1. **라이선스**: 상업 배포 합법? (MIT ✓, CC-BY-NC ✗, qwen-research ✗)
2. **VRAM 산술**: `파라미터 × 2바이트 (fp16)` 또는 `파라미터 × 0.55 × 1.3 (NF4)` ≤ 사용 가능 VRAM
3. **의존성 검사**: `transformers` 버전 호환, `bitsandbytes` 연산 능력 ≥ 7.5

**제거 순서**: 라이선스 → VRAM 산술 → 의존성 → 프로브 → 계약 테스트

### 3.4 로드 래더 (로컬 모델 운영)

```
1. fp16 로드 시도
2. 정상성 프로브: 비어 있지 않은 출력, 한글 존재, 반복 붕괴 없음
3. 프로브 실패 시 → 4bit NF4로 다운그레이드 (compute fp16)
4. 여전히 실패 시 → 진단과 함께 큰 소리로 중단
```

| 함정 | 증상 | 해결책 |
|---|---|---|
| `bnb_4bit_quant_type` 기본값 `"fp4"` | 조용한 품질 저하 | 명시적으로 `"nf4"` 설정 |
| `bnb_4bit_compute_dtype` 기본값 `float32` | 느린 추론 | `float16` 설정 |
| `device_map="auto"`가 파라미터를 meta 디바이스에 남김 | 조용한 부분 로드 | `device_map={"": 0}` 강제, 배치 확인 |
| T4에서 fp16 오버플로 (bf16 없음) | 쓰레기 출력 (조용히) | 정상성 프로브가 탐지; NF4 폴백 |
| 빈 예외 메시지 | `str(e)` == "" | `type(e).__name__` + repr + traceback 노출 |

### 3.5 추론형 모델 처리

| 모드 | TTFT | TTFA | 사용 사례 |
|---|---|---|---|
| **자연 모드 (think 포함)** | ~2.3s | ~15.1s | 사후 배치: 요약, QA 감사 |
| **스킵 (수동 프리필)** | ~0.2s | ~0.2s | 실시간 음성 에이전트 |

**핵심 인사이트**: 추론형 모델은 **실시간 음성 루프에서 제외**됩니다 (고객이 thinking을 침묵으로 듣게 됨) 하지만 **사후 배치 작업에는 가치**가 있습니다. 스킵 프리필은 템플릿 의존적이며 공식적으로 성능을 저하시킵니다.

### 3.6 스트리밍 아키텍처

| 구성 요소 | 구현 | 목적 |
|---|---|---|
| `TextIteratorStreamer` + 스레드 | 비차단 토큰 반복 | TTFT 측정 + 조기 TTS 핸드오프 |
| 문장 경계 분할 | `.?!` + 한국어 어미 기준 분할 | 전체 생성 전 TTS 시작 가능 |
| TTFS−TTFT 격차 추적 | 겹침 예산 측정 | TTS 파이프라인 설계 결정 |
| 토큰 스트림의 `async for` | 도착 즉시 토큰 처리 | 체감 반응성 |

### 3.7 파인튜닝 경로 (QLoRA)

| 측면 | 상세 | 비고 |
|---|---|---|
| **기법** | NF4 4-bit 고정 베이스 + fp16 LoRA 어댑터 (r=16, α=32) | QLoRA ≈ 4-6GB vs 전체 FT ≥18GB |
| **데이터 포맷** | 프롬프트-완성 쌍; 프롬프트 토큰은 −100 마스킹 | 포맷이 손실을 결정 |
| **검증** | 학습 전 모든 학습 예시가 계약 검증 통과 | 틀린 답을 가르치지 않기 |
| **타겟 모듈** | q/k/v/o/gate/up/down projection | 표준 LoRA 커버리지 |
| **가역성** | 어댑터 분리로 베이스 모델 복원 | 파인튜닝은 되돌릴 수 있음 |
| **OOD 프로브** | 미공개 시나리오 3개로 앵무새 현상 탐지 | 소규모 스타일 튜닝은 암기 위험 |

### 3.8 async/스트리밍 Python 메커니즘

| 패턴 | 사용 사례 | 핵심 규칙 |
|---|---|---|
| `asyncio.gather` | 병렬 I/O 대기 (LLM + TTS + ASR) | 대기를 겹치지 계산을 겹치지 않음 |
| `asyncio.to_thread` | async 맥락의 블로킹 라이브러리 | `time.sleep`이 루프를 얼림 |
| `asyncio.wait_for` | 외부 호출 타임아웃 상한 | 중단된 요청 방지 |
| 스트림의 `async for` | 도착 즉시 토큰 처리 | 전체 LLM 응답 전 첫 오디오 출력 |
| 취소 예절 | `CancelledError` 포착, 정리, 재발생 | 좀비 태스크 방지 |

### 3.9 멀티모달 / 옴니 모델

| 아키텍처 | 장점 | 단점 |
|---|---|---|
| **캐스케이드** (ASR → LLM → TTS) | 중간 전사 소유; 2-pass 가드; 컴포넌트 교체 가능 | 실패 지점 2+; 지연 합산 |
| **클라우드 단일 호출** (Gemini) | API 호출 1회; 코드 단순 | 중간 전사 없음; 벤더 종속 |
| **로컬 옴니** (Qwen2.5-Omni) | 데이터 주권; API 호출 없음 | 2-pass 가드 불가; 샘플률 변환(16k→24k); 한국어 품질 미검증 |

**옴니의 대가**: 모델이 system 프롬프트 슬롯을 소유하고, 중간 ASR 전사가 없으며, **2-pass 가드 루프가 구조적으로 불가능**합니다 — Talker가 Thinker의 hidden state를 직접 소비하기 때문입니다.

### 3.10 제공자 / 라우터 복원력

| 가드 | 구현 | 목적 |
|---|---|---|
| **카탈로그 가드** | `models.list()` + `supported_actions` 필터 | 목록에 있음 ≠ 호출 가능 |
| **생존 프로브** | 후보당 1토큰 실제 호출; 429 = 살아있음 | 죽은 모델 탐지 |
| **요율 게이트** | `RateGate` RPM 한도별 최소 간격 | 429 원인 추적 가능 |
| **모델별 능력 저하** | 모델별 `response_format` 지원 추적 | JSON 모드 폴백 |
| **DNP 추적** | Did-Not-Play(상위 제공자 포화)를 준수 실패와 분리 | 가용성 ≠ 품질 |
| **서버측 폴백 로깅** | 요청 모델 vs `resp.model` 비교 | 조용한 교체 탐지 |

## 4. lecture-note-ai 평가 프로토콜

### 4.1 테스트 트랙

| 트랙 | 입력 유형 | 지표 | 목적 |
|---|---|---|---|
| **클린 한국어** | 잘 구성된 강의 전사 | 준수율, 지연 | 기준선 |
| **노이즈 ASR** | CER > 0.15인 전사 | 환각 저항성 | ASR-LLM 통합 |
| **코드 스위칭** | 한국어 + 영어 기술 용어 | 한글 비율, 수동 검수 | 도메인 현실성 |

## 5. 실행 가능한 제안 (우선순위 순)

### P0: 계약 우선 LLM 모듈
- 검증된 계약을 반환하는 `generate(prompt, context=None) -> dict`를 갖춘 `src/llm/base.py` 구현
- 라이선스 + VRAM + 의존성 게이트를 갖춘 `src/llm/factory.py` 구현
- 요약 출력용 JSON 스키마: `{"summary": str, "key_points": list[str], "confidence": float}`
- 가드 생성 루프: JSON 모드 → 펜스 제거 → jsonschema → 재시도 → 폴백
- **근거**: 계약 우선이 기반; 모든 다운스트림 컴포넌트가 이에 의존

### P1: 프롬프트 계약 + 주입 방어
- PROMPT_CONTRACT 검증기: 역할, 예산, 데이터 펜싱
- 슬라이드 컨텍스트를 `<강의자료>` 태그로 주입 (명령 아님)
- ASR 신뢰도 변조: CER 낮음 → "요약 전 확인 요청" 지시
- 노트 포맷용 퓨샷 예시
- **근거**: 프롬프트가 위반율을 낮추고, 게이트가 보장 — 둘 다 필요

### P2: 로컬 모델 기준선 (Llama-3.2-Korean-Bllossom-3B)
- 비게이트, llama3.2 라이선스, T4에서 fp16 ~6.4GB
- 로드 래더: fp16 → 정상성 프로브 → NF4 폴백
- 5개 테스트 트랙에서 TTFT, TTFS, 준수율 측정
- **근거**: 라이선스, 크기, 한국어 지원, 생태계의 최적 균형

### P3: 스트리밍 통합
- TTFT 측정용 `TextIteratorStreamer` + 스레드
- 조기 TTS/노트 표시용 문장 경계 분할
- TTFS−TTFT 격차 추적 → `src/pipeline/stream_processor.py`의 겹침 예산
- **근거**: 실시간 강의 노트는 스트리밍 필요; TTFS가 다운스트림 게이팅

### P4: 대체 엔진 평가
- **Qwen3-8B (NF4)**: 더 강한 추론, Apache 2.0, 단 T4에선 NF4 전용
- **EXAONE-4.0-1.2B**: 가장 빠른 TTFT (~200ms), 최소 VRAM, 단 NC 라이선스가 상업 차단
- **Midm-2.0-Mini**: 한국어 네이티브, MIT 라이선스, 스타일 튜닝용 QLoRA 준비됨
- **Gemma-4-E2B**: 멀티모달 (오디오 직접 입력), Apache 2.0, 단 게이트 + 10GB
- 팩토리 패턴으로 교체 → 파이프라인 코드 변경 0

### P5: 실시간 async 파이프라인
- 병렬 ASR + LLM + TTS 대기용 `asyncio.gather`
- 블로킹 Whisper 추론용 `asyncio.to_thread`
- 모든 외부 호출에 `asyncio.wait_for` 타임아웃 상한
- 점진적 노트 표시용 토큰 스트림의 `async for`
- **근거**: 강의 노트는 실시간 갱신 필요; async가 대기를 겹침

### P6: 강의 스타일 파인튜닝 (QLoRA)
- 베이스로 Midm-2.0-Mini 또는 Llama-3.2-Korean-Bllossom-3B
- 타겟 노트 포맷과 일치하는 프롬프트-완성 쌍 40-100개
- 모든 학습 예시를 출력 계약에 대해 사전 검증
- QLoRA: NF4 베이스 + fp16 어댑터 (r=16, α=32)
- 앵무새 현상 탐지용 OOD 프로브
- **근거**: 프롬프트 + 퓨샷으로 일관된 노트 스타일이 안 될 수 있음; 파인튜닝이 사전을 이동

### P7: 강의 후 분석용 추론형 모델
- 강의 후 심층 요약용 DeepSeek-R1-Distill-1.5B
- 품질은 자연 모드 (thinking 포함), 속도 비교는 스킵 모드
- 실시간 아님 — 강의 종료 후 배치 처리
- **근거**: 추론형 모델은 복잡한 요약에 탁월하지만 실시간 루프에서 제외

### P8: 멀티모달 단일 호출 (선택)
- Gemma-4-E2B 오디오 직접 입력: 캐스케이드 없는 ASR+LLM
- 검증 가능성을 위해 전사를 명시적 계약 필드로 요구
- 데이터 주권: 실제 강의 오디오가 프로세스를 벗어나지 않음
- **근거**: 아키텍처 단순화하지만 2-pass 가드와 중간 전사 상실
